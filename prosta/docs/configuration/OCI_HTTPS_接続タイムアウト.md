# OCIでHTTPS接続がタイムアウトするときの確認事項

OCI上のサイトをHTTPからHTTPSへ切り替えた後、ブラウザーから接続するとタイムアウトする場合の確認メモ。

## まず確認すること

タイムアウトは、ブラウザーからHTTPSの待受先（通常TCP 443）まで通信が届いていない可能性を示す。証明書やTLS設定の問題では、一般にタイムアウトではなく証明書警告やTLSエラーになる。ただし、ネットワーク機器やサーバーが応答を破棄する構成では、TLS設定の問題でもタイムアウトに見える場合があるため、これだけで原因を断定しない。

## 確認箇所

1. **アクセス先とポート**
   - URLのホスト名が正しいパブリックIPまたはロードバランサーを指しているか確認する。
   - `https://ホスト名/` は通常443番ポートを使う。HTTPSを8443番など別ポートで待ち受ける構成なら、URLにもポート番号を指定する。
   - DNSを使う場合は、A/AAAAレコードが意図した接続先を向いているか確認する。

2. **OCIのネットワーク**
   - インスタンスへ直接接続する場合、適用されるNSGまたはサブネットのセキュリティ・リストに、必要な送信元からのTCP 443受信ルールがあるか確認する。
   - インターネットから直接接続する構成では、パブリックIPの割当て、サブネットのルート表にあるインターネット・ゲートウェイへの経路、ゲートウェイの有効状態も確認する。
   - OCIロード・バランサを使う場合は、リスナーがHTTPS/443を受け付けているか、バックエンド・セットとヘルス・チェックが正常か確認する。インスタンス側ではロード・バランサからバックエンドへの通信を許可する。
   - NSGとセキュリティ・リストは、実際に対象のVNIC/サブネットへ関連付けられているルールを確認する。

3. **サーバーの待受けとファイアウォール**
   - HTTPSを終端するコンポーネント（OCIロード・バランサ、Nginx/Apache、Tomcatなど）がTCP 443を待ち受けているか確認する。
   - OSのファイアウォールがTCP 443を許可しているか確認する。
   - HTTPからHTTPSへのリダイレクト設定だけでは、HTTPSの待受けは有効にならない。先に443番でTLS接続を受け付けるサーバーまたはロード・バランサの設定が必要。

4. **HTTPS終端の構成**
   - **ロード・バランサでTLS終端する場合:** クライアントからロード・バランサへHTTPS、ロード・バランサからTomcatへHTTPまたは構成したHTTPSで転送する。リスナー、証明書、バックエンド・ポート、ヘルス・チェックを一緒に確認する。
   - **TomcatでTLS終端する場合:** TomcatのHTTPSコネクター、証明書/キーストア、待受けポート、OS/OCIの通信許可を確認する。
   - HTTP側だけをHTTPSへリダイレクトしていて、転送先にHTTPSの待受けがない場合は接続できない。

## クライアントからの疎通確認

Windows PowerShellから、URLに使っているホストとポートへのTCP接続を確認する。

```powershell
Test-NetConnection <ホスト名またはIP> -Port 443
```

- `TcpTestSucceeded: False`: OCIの受信ルール、ルート、パブリックIP/DNS、OSファイアウォール、443番の待受けを順に確認する。
- `TcpTestSucceeded: True`: TCP接続はできている。ロード・バランサのTLSリスナー/バックエンド、TLS証明書・プロトコル、Webサーバー/Tomcatのログを調べる。ブラウザーに表示されるTLSエラーの内容も確認する。

この確認結果だけで原因が特定できない場合は、アクセスURL（秘密情報を含まない範囲）、ロード・バランサ経由かインスタンス直結か、`Test-NetConnection` の出力、サーバー側の待受け状態とログを組み合わせて切り分ける。

## セキュリティ上の注意

- 受信ルールは必要な送信元とポートに限定し、調査目的で広範囲なポートを恒久的に公開しない。
- 証明書の秘密鍵、キーストアのパスワード、DB認証情報を、ログや共有資料に貼り付けない。
