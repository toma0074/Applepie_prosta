## 3. HTTPS 化に必要なアプリ側の設定

### 3-1. リバースプロキシ / ロードバランサで TLS 終端する場合(推奨)
本番用プロファイルの properties(`application-aws.properties` など、使用中のもの)に追加する。ローカル開発(HTTP)に影響しないよう、`application.properties` には入れない。

```
server.forward-headers-strategy=framework
server.servlet.session.cookie.secure=true
```

- `forward-headers-strategy=framework`: `X-Forwarded-Proto` / `X-Forwarded-For` を信頼し、リダイレクトやリクエストの URL が `https://` として扱われるようにする。
- `cookie.secure=true`: セッション Cookie を HTTPS 通信でのみ送る。HTTP でアクセスするとログインが維持できなくなる。
- プロキシ側で `X-Forwarded-Proto` と `X-Forwarded-For` を必ず付与する。付与しないと `redirect:` が `http://` になる、または Cookie が送られない。
- 7778 を外部に公開すると、偽装した `X-Forwarded-*` を受け付けるため、公開しない。

### 3-2. Spring Boot 自身で TLS を終端する場合(非推奨)
```
server.port=443
server.ssl.enabled=true
server.ssl.key-store=file:/path/to/keystore.p12
server.ssl.key-store-type=PKCS12
server.ssl.key-store-password=${SSL_KEYSTORE_PASSWORD}
```
- 443 の bind に root 権限、またはポート転送(80/443 → 内部ポート)が必要。
- 証明書の更新(Let's Encrypt は 90 日)を自分で行う必要がある。
- キーストアのパスワードは環境変数などで渡し、リポジトリにコミットしない。

### 3-3. 補足(任意)
- HTTP→HTTPS のリダイレクトは、プロキシ / LB 側で行う(アプリには実装しない)。
- HSTS(`Strict-Transport-Security`)は、HTTPS が安定稼働してから有効化する。誤設定するとブラウザーが HTTP に戻れなくなる。
- 別課題: Spring Security 未導入のため CSRF 対策がない。HTTPS 化とは別に検討する。

### 4-3. 案 B: VM 上の nginx(または Caddy)でリバースプロキシ

- [ ] 443 で受けて `http://localhost:7778` に転送する設定

```nginx
server {
    listen 80;
    server_name example.com;
    return 301 https://$host$request_uri;
}
server {
    listen 443 ssl;
    server_name example.com;
    ssl_certificate     /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;

    location /prosta/ {
        proxy_pass http://127.0.0.1:7778;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

- [ ] SELinux が有効な場合、nginx から localhost への接続を許可(`setsebool -P httpd_can_network_connect 1`)

### 5-3. 接続できないとき
- タイムアウトの切り分けは [OCI_HTTPS_接続タイムアウト.md](./OCI_HTTPS_接続タイムアウト.md) を参照。
- 証明書警告 / TLS エラー: 証明書のドメイン名の一致、中間証明書を含む `fullchain` を設定しているか。
- 無限リダイレクト: プロキシが `X-Forwarded-Proto` を付与していない、または LB が HTTPS を HTTP でバックエンドに渡しているのにアプリが `forward-headers-strategy` を未設定。
- ログイン後にセッションが切れる: `cookie.secure=true` なのに HTTP でアクセスしている。
