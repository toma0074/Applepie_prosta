## 2. スライドごとの発表原稿

### 1: PROSTAとは / 20秒

PROSTAは、プログラミングや資格の学習を、継続しやすくするWebアプリです。
目指したのは、問題を解いて終わりにせず、結果から次の学習につなげることです。
今日は、その学習の流れを中心に紹介します。

### 2: 課題と目的 / 40秒

学習では、問題を解くこと自体より、その後に何を復習するかを決めることや、学習を続けることが難しいと考えました。
そこで、成績を見える形にし、履歴から復習へ進める流れを用意しました。
さらに、レベルやキャラクター、予定表、フレンドとの比較で、学習の積み重ねを感じられるようにしています。
効果を実証したというより、こうした課題を支える設計として実装しています。

### 3: 学習サイクル / 40秒

中心になるのは、解く、知る、やり直す、続ける、の四つです。
問題を解くと、採点と解説を確認でき、履歴やカテゴリ別の正答率に結果が反映されます。
復習モードは最後に間違えた問題、弱点問題は複数回の解答履歴から正答率が低い問題を対象にします。
最後に、成長要素と予定、フレンドが、次の学習を始めるきっかけになります。
動画では、このつながりを一人の利用者の流れとして紹介します。

### 4: デモの見どころ / 20秒

これから5分間のデモをご覧ください。
注目していただきたいのは、解答結果が復習につながること、学習の積み重ねが成長として見えること、そして予定と仲間が継続を支えることです。

ここで次のスライドへ。動画は自動再生にし、動画内ナレーションと発表者の声を重ねない。

### 5: デモ動画 / 300秒

後述の撮影表を使用する。動画には操作説明のナレーションと短い字幕を入れる。
編集で飛ばした箇所には「一部の解答操作を省略」などを表示し、連続操作や処理速度について誤解させない。

### 6: 技術・品質面 / 75秒

最後に、画面の裏側で工夫した点です。
PROSTAでは、採点結果だけでなく、EXPや実績も学習データとして扱います。このため、まとめて保存するトランザクションと、再読み込みによる二重保存を抑える処理を入れています。
また、複数タブで学習するときに状態が混ざらないよう、タブ別に状態を管理しています。同じアカウントは最後のログインだけを有効にしています。
今回、最新コードで既存294件を実行し、293成功、失敗とエラーはゼロ、1件は明示起動用テストのスキップでした。さらに、フレンド承認後に相手が削除された場合のテストを追加し、関連64件もすべて成功しました。二つの件数には重複があります。
構成はJava、Spring Boot、Thymeleaf、Oracleです。ただし今回の自動検証は隔離H2で、本番HTTPSやOracle固有動作まで確認済みとはしていません。

### 7: まとめ・今後 / 45秒

PROSTAで実現したのは、問題を解くだけの画面ではなく、その結果を次の行動につなげる学習体験です。
弱点を知って復習し、成長を確認し、次の予定を立て、フレンドの活動をきっかけにまた取り組む。この流れを一つのアプリにまとめました。
今後の候補は、まだ未実装のブックマークや全ユーザーランキング、対戦です。加えて、本番環境での確認を進めていきます。
解いて終わらない、次の学習につながる。以上、PROSTAの紹介でした。ご清聴ありがとうございました。

### 各区間の見せ方

- 1画面に長く留まらず、重要な数値・見出しの前後に2〜3秒の静止時間を置く。
- マウスカーソルを何度も振らない。注目箇所は字幕か枠で示す。
- 全問題への回答、スクロール待ち、通信待ちは編集してよい。ただし省略は字幕で示す。
- 既存履歴でグラフに偏りがある場合は「デモ用の過去履歴を含む」と伝える。今回の1回だけで弱点を断定したように見せない。
- BGMは必須ではない。入れる場合は利用許諾のある音源を使い、声を優先する。

## 4. 撮影前の準備

### 実行環境

1. **最新コードがビルド・起動された環境であることを確認する。** 既存のlocalhost:7778が最新とは限らない。
2. 専用の検証環境・デモアカウントを使用する。本番ユーザーの成績や個人情報を撮影しない。
3. 学習者と承認済みフレンドを1人ずつ準備する。動画では申請・承認の待ち時間を見せない。
4. フレンドには直近30日以内の学習記録を用意する。フィードが空でないことを確認する。
5. デモ用データとして、いくつかのカテゴリの解答履歴と、最後に不正解の問題を準備する。
6. 弱点出題も別途見せたい場合は、同じ問題を2回以上解き、全問正解ではない履歴が必要。メイン動画の操作は復習モードに絞る。
7. 同じアカウントで別ブラウザーからログインし直さない。最後のログイン以外が失効するため、録画中の画面が使えなくなる。

データ準備に[現状最新.sql](./db/現状最新.sql)を安易に実行しない。既存データを削除する再構築SQLであり、デモ準備のために本番へ適用しない。

### 表示と収録

- 1920×1080、16:9、30fpsを基本にし、文字が読める表示倍率へ調整する。
- 重要な内容が下に隠れないよう、スクロール位置を事前に決めておく。
- 個人情報、パスワード、通知、開発者ツール、不要なタブを映さない。
- 画面操作は区間ごとに録画し、ナレーションは後録りにすると失敗しにくい。
- カテゴリ演習は最大15問。区間の65秒に収めるには、途中操作のカットを前提にする。
- クエストやレベルアップを見せる場合、事前に到達条件を確認する。起きなかった変化を起きたように説明しない。

### 動画挿入

1. MP4（H.264映像・AAC音声）で書き出し、尺を正確に5:00へ合わせる。
2. PowerPointのスライド5を開き、「挿入→ビデオ→このデバイス」で挿入する。外部リンクではなく埋め込みにする。
3. 左の動画枠に合わせる。位置は左48pt・上155pt、サイズは幅608pt・高さ342pt（16:9）。
4. 元の紺色の枠と「ここに5分のデモ動画を挿入」等の案内文字を削除する。右側の「動画の流れ」は残す。
5. 再生開始は「自動」、ループなしに設定する。動画スライドをクリックで飛ばさないよう注意する。
6. スライドショーで頭から再生し、音量と最後の停止を確認する。終わったら手動でスライド6へ進む。
7. 発表PCにMP4単体も置き、埋め込み再生に失敗した場合の予備にする。PDF単体では動画は再生されない。
8. 動画挿入後、PDFを更新するなら動画の最初の画面をポスター画像に設定してから書き出す。

## 6. 質問された場合の回答メモ

**Q. フレンドが削除されたらどうなるか。**  
次の一覧取得で表示から除外され、ランキング対象にも入りません。フィードは404です。
削除された本人の既存ログインは次の認証済み要求で失効します。
論理削除なので関係と履歴は残り、管理者が復元すると再申請なしで戻ります。関係自体を解除した場合は戻りません。
この流れは今回、申請・承認・管理者削除・復元を通した回帰テストで確認しました。

**Q. どうしてゲーム要素を入れたか。**  
学習の積み重ねをレベルやキャラクターで見える形にし、継続のきっかけを作るためです。学習効果や継続率の改善を実証した段階ではありません。

**Q. 弱点問題と復習の違いは何か。**  
復習は各問題の最新解答が不正解のもの。弱点問題は同じ問題を2回以上解いた履歴から、正答率の低い問題を優先します。

**Q. テストは何件か。**  
変更前の全実行は294件で、293成功・1スキップ、失敗・エラー0です。その後、削除関連3件を追加して関連64件を実行し、すべて成功しました。
二つの実行には重複があり、358件成功とは言いません。また、追加後の全297件を一括再実行した結果ではありません。

**Q. 今後の優先順位は何か。**  
まず本番反映とOracle・HTTPS・スマホ実機の確認。その後、学習中に気になる問題を残せるブックマークが候補です。全体ランキングと対戦は別途設計が必要です。
